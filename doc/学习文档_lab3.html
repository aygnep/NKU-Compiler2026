先认识这些术语

AST / 访问者
AST 把语法结构组织成节点。apply(visitor,node) 根据具体节点调用对应 visit；同一棵树可被类型检查器和代码生成器分别遍历。
符号表 / 作用域
符号表记录一个名字在当前范围内代表什么。内层可遮蔽外层；离开块后内层名字失效。
属性 / 常量表达式
节点属性记录类型、是否能在编译时求值及其值。const 的值可用于数组长度和检测常量除零。
左值 / 地址 / 取值
左值指能定位存储位置的表达式。a=3 需要 a 的地址，a+3 需要从该地址 load 得到数值；const 不可写。
IR / SSA 寄存器
IR 是中间表示。每个 %regN 只定义一次，源程序变量可反复赋值，因此本阶段用 alloca 的内存槽及 store/load 实现变量更新。
基本块 / 终结指令
基本块是一段顺序执行的 IR。末尾必须由 br 或 ret 决定下一步；终结后不能再追加普通指令。
GEP / 行主序
getelementptr 根据元素类型、维度与下标计算地址，不会读取元素。行主序表示同一行的相邻元素连续存放。
数组退化 / 尾维
数组当作参数时传递首元素或首子数组的地址。形参首维可以省略，尾维决定跨行移动的步长。
短路 / PHI
&& 左侧为假、|| 左侧为真时跳过右侧。PHI 在合流块按实际来自哪个前驱选值，使逻辑结果也能参与运算。
i1 / i32 / float
LLVM 中分别是 1 位布尔、32 位整数和单精度浮点。zext、sitofp、fptosi 负责相应的扩展与转换。

跟着一个输入走完整个过程

1. 贯穿小程序：a + !a

输入：int main(){ int a=5; return a+!a; }
语法结构（教学示意）：Func(main) → Block → VarDecl(a,5)，Return(Binary ADD(LeftVal a, Unary NOT(a)))。
先进入全局、形参和函数体作用域。声明把 a 的 int 类型加入当前层；两个 a 的查找都命中这个声明。!a 的类型为 bool，外层 + 要将其提升为 int。因此结果为 5+0，程序返回值为 5。对应差异：符号表、decl_checker、expr_checker 与 stmt_codegen。

2. 从名字变成符号属性

Entry 只把名字 a 统一成可比较的对象，无法单独区分内外层同名变量。SymTable 用 vector<map> 的每一层保存各自 VarAttr，反向遍历查找，重复声明只比较当前 scopeLevel。LeftValExpr 把命中的属性复制到 resolved，离开作用域后不会悬挂地引用已经释放的 map 内容。形参与函数体分两层，按课程说明允许函数体声明同名局部变量。

3. 从属性生成指令

核心 IR（与实际输出一致的指令序列，寄存器编号可能随样例改变）：
%reg_1 = alloca i32
%reg_2 = add i32 5, 0
store i32 %reg_2, ptr %reg_1
%reg_3 = load i32, ptr %reg_1
%reg_4 = load i32, ptr %reg_1
%reg_5 = icmp eq i32 %reg_4, 0
%reg_6 = zext i1 %reg_5 to i32
%reg_7 = add i32 %reg_3, %reg_6
ret i32 %reg_7
alloca 建存储槽，store 写入 5，load 取数。!a 与 0 相等时为真；zext 保留布尔值的 0/1 含义。完整实际输出由下方回归命令重新产生，int_bool 用例同时检查 llvm-as、链接、返回值 5 与空标准输出。

4. 条件会改变下一条指令的位置

对 0 && tick()，左侧求值后直接跳到合流块，右侧 tick 所在块不会执行。合流 PHI 从左侧取 0，从右侧取比较后的值。嵌套逻辑可能创建新的合流块，所以记录右项计算完毕时的 curBlock 作为 PHI 前驱，不能用最初的右项入口块替代。算术辅助函数也要在递归返回后更新插入块，否则会把 add 插到已经终结的旧块。

5. 多维数组如何沿用同一条主线

int b[2][3]={{1,2},{3}} 展平为 [1,2,0,3,0,0]。语义阶段先检查维度，按对齐子数组递归填 initElements；空槽代表隐式零。全局从这个结果打印数组初值；局部先 alloca，再 memset 清零，仅对显式元素求值并 store。a[i][j] 使用 GEP；完整数组寻址前有 0 索引，形参数组已经是退化指针，首个索引用于选行。user f(int a[][3]) 要校验实参尾维 3，库 I/O 则按连续缓冲区校验元素类型。

6. 浮点转换与可观测行为

const int a=5; int b=a+3.5+!a 中，a 是 int，3.5 是 float，第一次 + 得 float；!a 是 bool，再转 float，相加仍是 float；初始化 b 时 fptosi 截断为 int，得到 8。变量若参与条件判断，数值与 0 比较产生 i1；float 用 une，保证 NaN 也被视为真。手册规定的常量整除零在语义阶段报错；普通运行期除数不为编译时常量时交给运行期。

为什么删去或替换旧代码

旧语句文件除表达式语句外都停在 未实现占位调用。函数、分支与循环的基本块构造由新实现负责，不再依赖虚构的顺序指令流。

为什么新增这些代码

函数先建 FuncDefInst/Function 和入口块，先为所有参数分配寄存器，再给标量参数建栈槽；数组直接绑定指针，函数体有独立名字作用域。遍历结束检查每个块，无终结时按函数类型补 return 0/0.0/void。BlockStmt 在遇终结后不再生成后续不可达语句，语义检查阶段仍已检查过它们。
ReturnStmt 求值并转换到函数返回类型。If 建 then/else/end，条件比较零为 i1；分支结束只在未终结时补到 end 的边。While 建 cond/body/end，continue→cond、break→end。For 额外有 step，continue→step；loops 栈在内层退出后恢复外层目标。所有递归访问结束都使用新的 curBlock，因此嵌套语句不会把回边错插在旧块。

对程序行为有什么影响

while 中 continue 重新判断条件，for 中 continue 仍执行 i=i+1。两边都 return 的 if 仍可能留下无前驱 end 块，补终结使 IR 合法；这不等于已经做了死代码优化。

nested_loop、for_continue、nearest_else、braced_else、short_return；全量官方测试都经过 llvm-as。

为什么新增这些代码

新增独立回归驱动：NEGATIVE 保存人工选取的错误输入和必要诊断片段，POSITIVE 保存独立算出的返回值及标准输出。每个正例都依次调用编译器、llvm-as、clang 链接并运行；每步非零都使该例失败。官方语义样例要求退出 1 且有 Error。--official 串行运行原 test.py，并解析 Passed 数量，因为官方脚本即使有失败也可能退出 0。
--native 用临时目录编译当前运行库及 globals.c，clang 包装器只提前指定库搜索路径；LLVM 14 的 llvm-as/clang 临时增加 opaque pointers 开关。shell 参数用 shlex.join，临时文件不纳入仓库。日志记录每个用例真实结果与错误输出。
